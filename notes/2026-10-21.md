# 2026-10-21 — App flow, dataset validation, and plotting

## Work covered today

Reviewed the existing implementation to explain how the webapp starts,
handles uploaded measurements, runs scientific analysis, and displays results.
This was a code walkthrough; no application behavior was changed.

## Startup and page loading

1. `make up` builds and starts the Docker app container.
2. Uvicorn loads the FastAPI application from `src/app/api.py`.
3. The backend initializes `DatasetStore` with the configured measurement
   directory. Compose sets `FMR_DATA_DIR=/data`, containing the bundled
   `broadband_100/` measurements.
4. Opening `http://127.0.0.1:8765` loads the HTML, CSS, JavaScript, and
   bundled Plotly library served by FastAPI.
5. `src/web/app.js` calls `analyze(true)` on page load, requesting
   `GET /api/analysis` for the active dataset and restoring its settings.
6. The browser displays the returned parameters and charts, then requests
   the selected measurement trace from `/api/measurements/{measurement_id}`.

The initial plots use supplied measurement files, rather than generated
placeholder values. Reloading the page uses the currently active dataset.

## Upload and dataset management

- The user selects the geometry and a folder of measurements. JavaScript
  collects CSV files and sends them with the analysis settings to
  `POST /api/datasets`.
- `src/app/dataset_store.py` stages the files in the container's `/tmp`,
  checks them, and runs the complete analysis before making them active.
- A successful upload replaces the active dataset, geometry, and fit
  initialization settings together. The previous uploaded directory is removed.
- A rejected upload is removed, and the previous dataset and settings remain
  active. The API returns an error for the browser to display.
- A lock keeps requests from reading a dataset while it is being replaced.
- Uploads are temporary: they survive browser reloads but are discarded when
  the container stops.

## What validation means

Validation checks whether the files can be read and processed by the analysis
pipeline before replacing the working dataset.

- File checks: a nonempty upload, no more than 1000 files or 100 MB total,
  nonempty CSV files, valid filenames, and no duplicate filenames after
  folder paths are stripped.
- Content checks, delegated to `src/app/pipeline.py`: a recognizable frequency
  in each filename, at least two columns per nonblank row, finite numeric
  field and signal values in the first two columns, and at least eight rows
  and eight distinct field values per sweep.
- Analysis checks: resonance fits and the selected Kittel model must complete;
  Kittel fitting requires at least four finite resonance points. Additional
  model checks include rejecting decreasing linewidth versus frequency,
  which would imply negative damping.

Passing validation does not establish experimental correctness or guarantee
a good fit. There is no minimum R² acceptance threshold. The application
assumes the expected input units and the user's selected geometry are correct.

## Scientific analysis and results display

After a successful upload, JavaScript requests `/api/analysis` again. The API
calls `pipeline.py`, which reads measurements, fits derivative-Lorentzian
resonances, extracts resonance fields and peak-to-peak linewidths, fits the
geometry-specific Kittel model, and derives damping from linewidth versus
frequency. The backend also generates the fitted plot curves.

The API returns JSON containing measurement summaries, fitted parameters,
fit quality, and curves. JavaScript fills the result cards and draws the
plots. Selecting a different sweep requests its raw trace and fitted curve
from the measurement endpoint.

The complete analysis currently runs during upload validation and again
when the frontend requests the results after upload.

## Plotting library

`src/web/app.js` uses Plotly.js for the Kittel dispersion chart, linewidth
versus frequency chart, and individual raw/fitted measurement trace. Plotly
also exports the charts as PNG images. The app does not directly use
Matplotlib, Three.js, or D3.js.

All scientific calculations, fits, and unit conversions happen in Python.
The browser handles rendering, label formatting, and user interaction.
